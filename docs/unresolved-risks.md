# Unresolved production risks

This register is the release-blocking remainder of the production-grade review.
`OPEN` means the repository has not yet demonstrated the stated scope. A risk
may have substantial implementation and test coverage while remaining open
because managed infrastructure, representative capacity, or external operator
evidence is still missing.

| ID | Severity | Status | Risk | Current evidence | Exit evidence |
|---|---|---|---|---|---|
| P0-01 | P0 | OPEN | A managed Redis failure during worker execution could delay or duplicate accepted jobs beyond the tested local recovery boundary. | Real-Redis worker-kill, lease, duplicate-delivery, cancellation, restart, and restore tests run in CI. | Managed Redis failover drill shows accepted jobs reach one terminal state, with retry/DLQ and recovery artifacts attached to the release commit. |
| P0-02 | P0 | OPEN | Redis state transitions and audit durability are not proven across managed failover and rolling schema changes. | Atomic scripts, versioned envelopes, multi-process idempotency tests, and disposable Redis restart/restore evidence exist. | Managed failover plus mixed-version rollout demonstrates recoverable idempotency, cache, job, rate-limit, and audit state without silent corruption. |
| P0-03 | P0 | OPEN | Some model, dependency, audit, timeout, cancellation, and transport combinations still lack one complete externally visible failure matrix. | Synchronous, batch, stream, and job regression tests cover major detector, policy, audit, timeout, Redis, and cancellation paths; inline policies are now validated fail-closed. | Every matrix cell has a named test and confirms generic errors, no raw pass-through, bounded cleanup, and documented status semantics. |
| P0-04 | P0 | OPEN | Collector-side telemetry delivery and privacy are not verified outside the in-process OTLP receiver canary. | Metadata-only spans, bounded exporter buffering, export-failure metrics, and a real local OTLP gRPC delivery test exist. | External collector canary verifies delivery, retry/drop behavior, and absence of request values in received logs, metrics, and traces. |
| P0-05 | P0 | OPEN | Future releases do not yet have recurring evidence attached for every supply-chain and release gate. | Current release workflows generate SBOMs, scan images, sign images, and publish provenance. | A subsequent release demonstrates exact-SHA test/security/performance gates, artifact-to-commit/model/lockfile binding, and documented exception handling. |
