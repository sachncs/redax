# Failure-mode matrix

This matrix states the current externally visible behavior and the production
behavior required by the plan. “Current” is not automatically “acceptable for
HA”; gaps are marked explicitly.

| Dependency or event | Current behavior | Safety posture | Production acceptance condition |
|---|---|---|---|
| API keys missing in `prod` | Startup fails validation. | Fail closed. | Keep; add scoped principal/rotation evidence. |
| Trusted hosts missing in `prod` | Startup fails validation. | Fail closed. | Keep; document proxy/TLS boundary. |
| Redis unavailable at startup | App logs and retains a reconnect-capable store; cache/idempotency are skipped or fail closed, durable job admission remains unavailable until the ARQ queue reconnects, and rate limiting fails closed unless explicit fail-open. | Mixed, explicit. | Required readiness stays 503 until Redis and the queue recover; the API recovery loop and disposable Redis drill cover reconnect behavior. |
| Redis unavailable during rate limit | Returns typed 503 by default; explicit `REDAX_RATE_LIMIT_FAIL_OPEN=true` allows traffic. | Configurable, documented. | Require explicit operator acknowledgement and alert on fail-open. |
| Redis unavailable during cache | Request recomputes; cache is skipped. | Fail open for optimization only. | Never let cache failure change redaction semantics. |
| Redis unavailable during jobs | Redis client failures are normalized as transient dependency errors; required Redis readiness performs a bounded ping and returns 503; new durable-job submissions return 503, while already accepted jobs depend on Redis durability and recovery. | Unsafe without HA/failover evidence. | Verify Redis HA, enqueue recovery, lease expiry, and worker retry/DLQ behavior. |
| Model cannot load in `prod` | Startup fails; dev may log and downgrade according to detector configuration. | Fail closed in prod. | Add readiness/startup and corrupted-model tests. |
| Model inference failure | Pipeline can use an explicit regex fallback and records fallback when regex spans are available; if the model fails and regex finds no spans, the pipeline rejects the request with a generic 503 instead of returning raw text. Policy paths return an error. Batch/stream detector exceptions emit only generic failure output and do not echo input values. | Degraded, fail closed when no safe fallback exists. | Keep fault-injection coverage and the documented policy matrix. |
| Model timeout | Synchronous request returns 504; job marks failure; stream emits timeout event. | Reject/fail closed. | Add cancellation and recovery tests. |
| Circuit breaker opens | Pipeline uses its explicit fallback marker; the production path coordinates open/probe state through a namespaced Redis hash, while Redis coordination failure uses the local breaker as an explicit load-shedding fallback. | Degraded, observable. | Keep shared-breaker Redis concurrency coverage and HA Redis evidence in the release gate. |
| Policy file missing/invalid | Validation/loading error prevents normal policy execution. | Reject. | Startup validation for required default policy and tests for rolling compatibility. |
| Audit backend unavailable | `REDAX_AUDIT_REQUIRED=true` rejects processing when the backend is uninitialized, has failed, or its bounded queue is full; mandatory-audit failure also makes `/readyz` return 503. Optional mode records a metric and continues. File mode uses JSONL; Redis mode uses a bounded centralized metadata-only list and refuses startup without Redis. | Configurable, fail closed by default. | Verify centralized retention, managed Redis durability, and disk-failure propagation end to end. |
| Disk full / permission failure | File audit write failure is counted/logged and required mode synchronously acknowledges each event, so the first failed write rejects the request and marks the backend unavailable. | Fail closed on the first failed write. | Keep durable managed-audit evidence and recovery drills in the release gate. |
| Telemetry exporter unavailable | OTLP is optional; request processing should continue. | Fail open for telemetry. | Bound exporter buffers and verify no raw attributes. |
| Request too large | 413 for configured body-byte limit, including chunked bodies, and configured text limit; batch/stream have their own bounds. | Reject. | Add batch amplification and response-size limits. |
| Slow request body | Chunked bodies must arrive within `REDAX_REQUEST_BODY_TIMEOUT_SECONDS`; otherwise return 408 before parsing. | Reject. | Tune the timeout to the ingress/client contract and alert on repeated body timeouts. |
| Invalid or adversarial Unicode | Pydantic and code-point chunking validate input; property tests cover parts of the transform path. | Bounded in tested paths. | Add fuzz suite and CPU/memory budgets. |
| Client disconnects from stream | Stream cancellation is classified as status `499`, recorded in the stream span without request values, and generator cleanup always observes end-to-end latency; no audit event is emitted for an incomplete stream. | Bounded cancellation cleanup. | Keep signal-driven disconnect/shutdown integration coverage in the release gate. |
| API process dies | In-flight synchronous work is lost; safe because no response is emitted, but client retry semantics apply. Redis idempotency and the model breaker coordinate across surviving replicas. | Bounded. | Multi-replica retry/idempotency semantics must remain covered by the Redis integration gate. |
| SIGTERM / graceful shutdown | Readiness drops before cleanup; admitted HTTP requests and a backpressured active stream are exercised by process-level SIGTERM tests, and ARQ stops picking new jobs while allowing active jobs to finish within the validated `REDAX_SHUTDOWN_TIMEOUT_SECONDS` window before cancelling/releasing remaining work. Queue, audit, and Redis cleanup then share the remaining budget. | Bounded, with forced cleanup after the deadline. | Re-run the same signal contract during the reference deployment rollout drill. |
| Worker dies mid-job | ARQ retries failed attempts; its in-progress lease expires at the bounded worker timeout and another worker can claim the queued job. Queued jobs can be atomically cancelled; running jobs remain worker-owned. Exhausted failures enter a bounded, payload-free Redis dead-letter list. | PARTIAL. | `tests/integration/test_redis_jobs.py::test_real_redis_job_recovers_after_worker_process_kill` and `test_real_redis_queued_job_can_be_cancelled` prove the current paths; Redis failover and production-scale drills remain required. |
| Duplicate job delivery | An atomic queued-to-running claim permits one worker delivery; later deliveries observe running/terminal state and do no work. Terminal completion is also atomic and releases capacity once. | Fail closed for malformed state. | `tests/integration/test_redis_jobs.py::test_real_redis_job_claim_allows_one_duplicate_delivery` and terminal-transition concurrency coverage. |
| Rolling deployment | API replicas share versioned Redis state; cache readers treat incompatible envelopes as misses, idempotency readers reacquire incompatible records, and durable-job transitions refuse incompatible schemas. | Bounded for tested schema paths; deployment remains gated on state migration evidence. | Keep mixed-version Redis/schema tests and rollback verification for every persisted-schema change. |

## Operator rule

When the chosen deployment mode cannot preserve the required privacy or
durability boundary, mark the instance unready or reject the request. Do not
silently downgrade a security-sensitive operation to pass-through.
